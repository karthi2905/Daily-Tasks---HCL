## 1. AI-Generated Snippet

The following booking conflict check was generated by GitHub Copilot when I prompted it with:

> "Write a Java method to check if a new booking time slot overlaps with existing bookings"

**Copilot-generated output:**

```java
public boolean isAvailable(LocalDate date, LocalTime startTime, LocalTime endTime) {
    for (Booking existing : bookings) {
        if (existing.getDate().equals(date)) {
            // Check if the new start time falls inside an existing booking
            if (!startTime.isBefore(existing.getStartTime())
                    && startTime.isBefore(existing.getEndTime())) {
                return false;
            }
        }
    }
    return true;
}
```

---

## 2. What the Snippet Was Supposed to Do

The method should return `false` (resource not available) whenever the requested time slot `[startTime, endTime)` overlaps with any existing confirmed booking on the same date.

It should handle:
- Partial overlap from the left (new booking starts before existing ends)
- Partial overlap from the right (new booking ends after existing starts)
- New booking completely containing an existing booking
- Existing booking completely containing the new booking
- Adjacent bookings (no overlap — only touching at endpoints)

---

## 3. Problem Found

The generated code only checked whether the **new start time** fell **inside** an existing booking:

```java
!startTime.isBefore(existing.getStartTime())   // newStart >= existingStart
    && startTime.isBefore(existing.getEndTime()) // newStart <  existingEnd
```

This misses the case where the **new booking completely contains the existing booking**.

### Example that fails with the AI-generated code

Existing booking: `10:00 - 11:00`

New request: `09:00 - 12:00`

Evaluation with AI code:
- `startTime (09:00) >= existing.getStartTime() (10:00)` → **FALSE**
- Short-circuits: the second condition is never evaluated.
- Result: **returns `true` (available)** — **INCORRECT**.

The new booking `09:00 - 12:00` completely contains the existing booking `10:00 - 11:00`.
They clearly conflict, but the AI code misses this case entirely.

---

## 4. Why It Was Wrong

The AI-generated check is a **subset-of-start-time** check, not a true **interval overlap** check.

It only asks: "Does the new start time land inside an existing booking?"

It does not ask: "Does any part of the new booking's duration touch any part of the existing booking's duration?"

The correct formulation for **interval overlap** is:

```
Two intervals [A, B) and [C, D) overlap if and only if:
    A < D  AND  B > C
```

Where:
- A = new start, B = new end
- C = existing start, D = existing end

This single condition covers **all four** cases:
1. A < D and B > C → partial left overlap
2. A > C and B < D → new is inside existing
3. A < C and B > D → new completely contains existing  ← **missed by AI code**
4. A = C and B = D → exact match

---

## 5. Corrected Implementation

```java
@Override
public boolean isAvailable(LocalDate date, LocalTime startTime, LocalTime endTime) {
    for (Booking existing : bookings) {
        if (existing.getDate().equals(date)
                && existing.getStatus() != BookingStatus.CANCELLED
                && existing.getStatus() != BookingStatus.REJECTED) {

            // Correct interval-overlap formula:
            //   newStart < existingEnd  AND  newEnd > existingStart
            boolean overlaps = startTime.isBefore(existing.getEndTime())
                    && endTime.isAfter(existing.getStartTime());

            if (overlaps) {
                return false;
            }
        }
    }
    return true;
}
```

**Additional improvements over the AI-generated version:**

1. Added status check: cancelled/rejected bookings should not block new bookings.
2. Used the complete interval-overlap formula (`A < D AND B > C`).
3. Adjacent bookings (e.g., 09:00-10:00 and 10:00-11:00) correctly return `true` (available).

## 7. Final Result

The corrected method is implemented in [`Resource.java`](../src/main/java/com/technova/booking/model/Resource.java) in the `isAvailable` method.

The AI-generated code was a useful starting point but contained a logical flaw that would have allowed double-booking in a real-world scenario — a significant business bug. This illustrates why AI-generated code always requires careful human review and thorough testing.

**Lesson learned:** Always test boundary and containment cases when implementing interval-overlap logic.
